World Age Database Schema

The map-owned world age catalog is stored in Data/map/maps.db. A match follows one route through the selected map's age candidates. Age IDs are stable runtime and save-game keys; level gates use logical stages. The active schema combines stages with explicit age_transition edges: the map's ordered age_ids list supplies candidates and deterministic tie-breaking, while transition rows select the active branch.

Static Content

map(
    id PRIMARY KEY,
    xmlName,
    name,
    age_ids TEXT
)

age(
    id PRIMARY KEY,
    stage,
    name  -- localization key, e.g. age_3
)

condition(
    id PRIMARY KEY,
    metric,  -- 0: workers, 1: army
    target
)

age_condition(
    age_id REFERENCES age(id),
    condition_id REFERENCES condition(id),
    PRIMARY KEY(age_id, condition_id)
)

age_transition(
    age_id REFERENCES age(id),
    next_age_id REFERENCES age(id),
    PRIMARY KEY(age_id, next_age_id)
)
FieldMeaning
age.idStable age ID. Age 0 is the root.
age.stageLogical progression stage used by level gates. Multiple candidate ages can share a stage.
condition.idStable reusable condition ID. A condition may be joined to multiple ages.
metric0 counts workers; 1 counts non-worker army units.
targetRequired average metric across all configured players.
Progression policy: all conditions joined to one candidate age must be met on the same simulation tick. The first qualifying candidate in the map's ordered age_ids list wins. After 18,000 simulation ticks, the candidate with the greatest condition progress wins; ties use map order.

Canonical Age Sequence

The canonical content has seven age IDs grouped into four logical stages. Explicit transition rows define the selected branch:

stage 0: 0  I - Settlement

stage 1: 1  II - Growth       workers 10
          2  II - Mobilization army 20

stage 2: 3  III - Consolidation workers 20
          4  III - Fortification army 30

stage 3: 5  IV - Industry      workers 40
          6  IV - Conquest      army 70

The transition rows are 0 -> 1,2, 1 -> 3, 2 -> 4, 3 -> 5, and 4 -> 6. When multiple direct candidates complete on the same tick, the order in the selected map's age_ids list is the deterministic tie-break.

Level Gates

unit_level.age_stage and building_level.age_stage are part of the normal level tables. A level is available after the current selected age reaches at least that logical stage, regardless of which candidate age won at that stage.

RequirementPurpose

Save Data

Scene saves do not duplicate static age content. They preserve the current state for the map selected by config.map:

TableStored data
world_ageOne row containing current_age, age_started_tick, and history.
world_age.historyComma-separated age IDs reached on the selected map route, for example 0,2,3,4. The final ID must equal current_age.

Changing age IDs requires a compatibility decision and a save migration. The age start tick must be preserved when migrating a save so the timeout does not reset unexpectedly.

Implementation

DatabaseCache validates age references, condition targets, map candidate IDs, stage ordering, and level-stage bounds. WorldAgeController evaluates worker and army averages across the configured players, applies the 18,000-tick timeout fallback, and persists the selected route and age start tick. The current save schema has no separate transition, hold, or history table.
