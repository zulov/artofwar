Scope

SceneLoader opens the filename passed by Main below saves/ without changing it, validates the five required tables and their required column names, and reads the save into dbload_container. The one-row config table carries precision/map/size, simulation ticks, and RNG continuation; it has no active schema-version field or camera state. It does not create game objects or resolve cross-entity references. Entity creation and runtime-link restoration happen later through Simulation and Main.

Related code: game/src/scene/load/SceneLoader.cpp reads SQLite into DTOs, game/src/simulation/Simulation.cpp constructs entities and restores runtime state, and game/src/Main.cpp performs the final startup restoration.

Load Order

1
SceneLoader::createLoad()
Open the save read-only, require config, players, units, buildings, and resources, validate their required column names, require exactly one valid config row, restore its RNG fields, and read optional runtime rows while SQLite is open.
2
SceneLoader::load()
Read base players, units, buildings, and resources DTOs, then close SQLite.
3
Simulation::loadEntities()
Construct base entities and rebuild static grids.
4
Simulation::restoreRuntimeState()
Build the physical UID map, restore formations, unit links, aims, orders, embedded building targets, levels, queues, AI/resource state, RNG from config, and projectiles.
5
Main::load()
Refresh influence and visibility maps, use the normal GUI camera setup, restore deferred commands, close the loader, reset the frame service, then restore the persisted total tick count. Wall time, the render accumulator, and the real-frame flag remain reset.

UID Resolution

Runtime rows store cross-entity links as UIDs because a target can be a unit, building, or resource. They must not be resolved in SceneLoader: referenced entities exist only after stage 3.

Simulation::restoreRuntimeState() builds one lookup over all physical entities:

units.uid + buildings.uid + resources.uid -> Physical*

It uses that lookup for target_uid, aim_target_uid, projectiles.aim_uid, formation members, and deferred-command entity lists. Missing or invalid UID links are skipped rather than creating a replacement object.

Compatibility

Variable-length runtime tables are optional. Mandatory unit continuation, building combat state, player resource state, simulation ticks, and RNG state are read from the required units, buildings, players, and expanded config rows. GUI camera state is intentionally recreated by normal startup. The checked-in quicksave.db and quicksave512.db files now use the current required schema; intermediate copies can be migrated with docs/quicksave-migration.txt. A genuinely older five-table save with missing required columns uses docs/old-save-migration.txt. A save from the immediately previous pre-consolidation format, with a four-column config plus random and camera singleton tables, uses docs/config-table-migration.txt.

Save writes use named columns, and loads use explicit column lists generated from the enums in game/src/database/db_columns.h. Physical SQLite column order and extra columns do not affect the current loader, but required names and enum order must remain aligned. A save-schema change must update the matching SQL definition, enum, save binding, and load binding together. The format has no active schema-version field, so there is no automatic schema migration; saves missing required tables or columns must be migrated explicitly or regenerated.

Validation

  1. Copy and migrate a legacy five-table save, then confirm base entities load with continuation fields initialized by the migration defaults.
  2. Load a runtime save with targets, queued work, formations, projectiles, and pending commands.
  3. Confirm every UID link is resolved only after entity creation and static-grid refresh.
  4. Run tests.exe --gtest_filter=PersistenceRowTest.*:PersistenceStateTest.* and a game save/load smoke test.
